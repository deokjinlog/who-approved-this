# T1c 결재선 예측 — 무엇을 알았으면 맞혔을까

leave-one-out 결과에서 예측이 틀린 지점마다 **어떤 정보가 있었으면 맞힐 수
있었는지** 정리한다. 회사 기능 ②(결재라인 자동 삽입)에 어떤 입력이 필요한지를
공개 데이터로 먼저 확인하는 게 목적이다.

실명은 적지 않는다. 문서는 문서번호로, 사람은 직위로만 가리킨다.

| 코드 | 뜻 |
|---|---|
| `조직정보` | 어느 기관·팀이 있고 누가 그 직위인가 |
| `전결규정` | 이 문서가 어느 직위까지 올라가는가 |
| `문서유형규칙` | 지출은 경리 협조 필요 등, 문서 성격에 따른 결재선 규칙 |
| `표본한계` | 데이터가 적어서 생긴 문제 |

---

## 1. `조직정보` — 포털 부서명으로는 조직을 식별할 수 없다 (가장 큰 원인)

**법무부 "총무과" 8건은 실제로 6개 서로 다른 조직이다.**

포털 메타데이터는 8건 모두 `생산기관=법무부`, `담당부서=총무과`, 기관코드 `1270000`
으로 **완전히 동일**하다. 실제 조직은 문서 하단 주소에만 드러난다.

| 실제 조직 (주소 기준) | 문서 수 | 결재선 직위 패턴 |
|---|---|---|
| 안양교도소 | 2 | 교감 → … → 부소장 → **안양교도소장** |
| 대구합동청사 | 2 | 교위/교감 → 총무사무관 → … → **청장** |
| 서울출입국·외국인청 | 1 | 출입국관리서기 → 주사보 → 주사 → 총무과장 → **청장** |
| 인천공항출입국·외국인청 | 1 | 출입국관리주사보 → 팀장 → 총무과장 → 지원국장 → **청장** |
| 광주합동청사 | 1 | 교위 → 교감 → 총무사무관 → 총무과장 → **청장** |
| 대전통합청사 | 1 | 교위 → 총무사무관 → 총무과장 → **청장** |

직위 체계부터 다르다(**교정직** 교위·교감·부소장 vs **출입국관리직** 서기·주사보·주사).
최종 결재자도 소장/청장으로 갈린다. 부서명만 보고 묶으면 예측이 성립하지 않는다.

- **필요 정보: `조직정보`** — 부처가 아니라 **소속기관 단위까지 내려간 조직 코드**.
  포털에는 그 필드가 없고, `nstCd` 도 부처 단위라 구분되지 않는다.
- **회사 환류**: 이관 700만 건에서 **부서명은 기관 간에 재사용된다**
  ("총무과"는 거의 모든 기관에 있다). 조직 키 없이 부서명으로 결재선을 묶으면
  전혀 다른 조직의 결재선을 학습·제안하게 된다.
- 이 8건을 조직으로 다시 가르면 **2건 이상인 조직이 둘뿐**(안양교도소, 대구합동청사)이라
  예측 가능한 케이스가 4건으로 줄었다. 나머지 4건은 참고할 과거 문서가 없어 제외했다
  (`표본한계`).

## 2. 경기도서관 8건 — 케이스별

같은 조직 8건이라 조직 문제는 없다. 여기서 남는 오차가 **순수하게 필요한 정보**다.

| 문서 | 문서 성격 | 검토 직위 | 칸 수 |
|---|---|---|---|
| 8872 | AI 스튜디오 투어 프로그램 운영 계획 | 도서관운영팀장 | 3 |
| 8938 | AI 협업 프로젝트 추진 결과 보고 | 도서관운영팀장 | 3 |
| 8942 | 스튜디오 프로그램 기성검사 완료 알림 | 도서관운영팀장 | 3 |
| 11698 | 스튜디오 프로그램 기성검사 결과 보고 | 도서관운영팀장 | 3 |
| 12039 | **독서** 코칭 운영 용역 기성검사 결과 보고 | **독서문화진흥팀장** | 3 |
| 12016 | 의원 요구자료 제출 | **도서관정책팀장** | 3 |
| 10185 | 정수기 렌탈료 **지출** 건의 | 도서관운영팀장 + **도서관정책팀장** | **4** |
| 12012 | 초과근무수당 **지출** | **도서관정책팀장** + 협조(주무관·**경리팀장**) | **5** |

### 2-1. 팀 배정 — `조직정보` (다만 제목에서 유추 가능)

사업 문서는 `도서관운영팀장`, 서무·예산 문서는 `도서관정책팀장`,
독서사업은 `독서문화진흥팀장` 이 검토한다.

- **필요 정보: `조직정보`** — 기관의 팀 목록과 업무분장.
- 다만 **팀 이름에 업무가 드러나 있다**("독서문화진흥팀" ← "독서 코칭").
  팀 목록만 주면 LLM이 제목에서 맞힐 수 있고, baseline 은 제목을 안 읽으므로
  **구조적으로 불가능**하다. **baseline 대비 LLM 이득이 나와야 하는 첫 번째 지점.**

### 2-2. 지출 문서는 결재선이 길어진다 — `문서유형규칙`

3칸이 기본인데 **지출 문서 2건만 4칸·5칸**이다.

- 10185(정수기 렌탈료 지출) → 운영팀장 **위에 정책팀장이 하나 더** 붙는다.
- 12012(초과근무수당 지출) → 정책팀장 + **경리팀장 협조**가 붙는다.

- **필요 정보: `문서유형규칙`** — "지출은 예산 담당(정책팀·경리팀)을 경유한다".
  제목에 "지출"이 그대로 있어 **제목만 보고 유추 가능한 규칙**이다.
  **baseline 대비 LLM 이득이 나와야 하는 두 번째 지점.**
- 칸 수 불일치의 주원인이 이것이다(경기도서관 칸수 93.8%).

### 2-3. 전결·대결 — `전결규정`

8건 중 7건이 `경기도서관장` 전결이고, 10185 는 관장 전결 + **정책팀장 대결**이라
관장 칸에 이름이 인쇄되지 않았다(gold `?`, 이름 채점 제외).

- **필요 정보: `전결규정`** — 누가 어느 문서를 전결하는지, 부재 시 누가 대결하는지.
  제목·본문으로는 알 수 없다. 최종 결재 칸의 **이름**을 좌우한다.

## 3. 과거 문서 몇 건이면 충분한가 — `표본한계`

경기도서관 8케이스에서 참고 문서 수만 바꿔 `baseline_vote` 를 다시 쟀다(같은 케이스 집합).

| 참고 문서 | 직위 | 이름 | 칸 수 |
|---|---|---|---|
| 1건 | 61.3% | 27.5% | 93.8% |
| 3건 | 61.3% | 27.5% | 93.8% |
| **7건** | **81.0%** | **48.3%** | 93.8% |

**1건과 3건이 완전히 같다.** 참고가 적으면 다수결이 사실상 "최근 문서 복사"로
무너지기 때문이다. 7건에서야 실제 다수 패턴(운영팀장이 기본)이 드러나 직위가 20%p 뛴다.

- **회사 환류**: 결재선 추천을 과거 이력으로 하려면 **부서·조직당 최소 5~7건**은
  있어야 통계가 의미를 갖는다. 신설 부서나 문서가 적은 조직은 규칙·조직도 기반
  fallback 이 필요하다.

## 4. 정리 — 결재라인 자동 삽입에 필요한 입력

우선순위 순.

1. **`조직정보` (필수)** — 소속기관 단위 조직 코드 + 팀 목록 + 업무분장.
   부서명만으로는 기관이 갈리지 않고(법무부 총무과 = 6개 조직), 팀 배정도 못 한다.
2. **`문서유형규칙` (효과 큼)** — 지출→예산팀 경유·경리 협조 같은 규칙.
   제목만으로 유추 가능한 것이 많아 LLM이 가장 이득을 낼 영역이고,
   칸 수 불일치의 주원인이다.
3. **`전결규정`** — 전결·대결 주체. 최종 결재 칸의 이름을 좌우한다.
4. **`표본한계`** — 조직당 과거 문서가 5~7건은 있어야 이력 기반 추천이 작동한다.

## 5. LLM 케이스 (미실행)

`llm_local` 은 아직 돌리지 않았다. 모델이 정해지면 같은 케이스를 돌리고
**틀린 케이스마다 위 분류로 한 줄씩** 여기에 덧붙인다. 특히 확인할 것:

- 12039 의 팀 배정을 제목("독서")에서 맞히는가 → `조직정보` 없이 가능한가
- 10185·12012 의 지출 경유·협조를 제목("지출")에서 붙이는가 → `문서유형규칙`
- 참고 문서를 **그대로 베끼지 않는가** — 베끼면 baseline 과 같아지고,
  이름을 지어내면 더 나쁘다(gold 에 없는 사람을 만들어내는지 확인)
