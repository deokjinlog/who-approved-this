# T1d 품의서 초안 — 초안이 못 채우는 것은 무엇인가

제목만 주고 같은 조직 문서를 검색해 초안을 쓰게 했을 때, **검색·생성으로는 끝내
채울 수 없는 정보**가 무엇인지 정리한다. 회사 요구사항의 "첨부 + 연결문서 기반
RAG 생성"이 왜 필요한지가 여기서 나와야 한다.

실명·금액 실값은 적지 않는다. 무엇이 비는지만 적는다.

| 코드 | 뜻 |
|---|---|
| `첨부정보` | 금액·수량·기간 등 첨부물에만 있는 값 |
| `연결문서` | 앞선 문서(기획→실행, 요청→회신)를 알아야 쓸 수 있는 내용 |
| `조직관행` | 그 조직이 늘 쓰는 항목 구성·말투 |
| `기타` | 위에 안 들어가는 것 |

---

## 1. 검색 단계 결과 (BM25만, 임베딩 모델 대기)

경기도서관 8건 leave-one-out, 대상 **제목만**으로 검색.

| 방식 | 같은 조직이 top-3에 | 같은 유형이 top-3에 | top-5의 서로 다른 문서 수 |
|---|---|---|---|
| **`bm25`** | **2.38 / 3** | 75.0% | 4.62 |
| `vector` (bge-m3) | 2.00 / 3 | 75.0% | 4.62 |
| `hybrid` (RRF) | 2.25 / 3 | 75.0% | 4.38 |

**BM25 가 이겼고, 임베딩은 도움이 안 됐다.** 세 방식의 같은 유형 적중률이 75.0% 로
완전히 같다는 게 핵심이다 — 유형을 가르는 건 검색 방식이 아니다.

이유는 데이터 성격에 있다. 제목에 조직명("경기도서관")이 **문자 그대로** 들어 있어
어휘 매칭이 이미 강하고, 청크가 43개뿐이라 의미 검색이 이득을 낼 여지가 좁다.
하이브리드가 BM25 를 못 넘은 것도 벡터 쪽 순위가 섞이며 오히려 끌어내렸기 때문이다.
**이 규모에서는 BM25 만으로 충분하다.**

제목만으로도 같은 조직 문서가 top-3에 평균 2.4건 들어온다. 조직 이름("경기도서관")이
제목에 자주 들어가서다. 같은 **유형**을 찾는 건 75%로 더 어렵다 — "기성검사 결과 보고"와
"초과근무수당 지출"은 어휘가 겹치지 않는다.

## 2. 실제 문서에 있는데 초안이 알 수 없는 것

경기도서관 8건의 실제 본문을 항목 단위로 훑은 결과. **생성 전에 이미 확정된 한계**다.

### 2-1. `첨부정보` — 지출 문서의 본문은 사실상 전부 수치다

지출 문서 2건(10185, 12012)만 번호 항목을 갖는데, 그 항목이 전부 값이다.

| 항목 | 값의 출처 |
|---|---|
| 지급액 | 첨부(명세서·청구서) |
| 산출내역 | 첨부(수량·단가) |
| 사용기간 / 근무기간 | 첨부 |
| 지급대상 | 첨부(업체명·인원수) |
| 예산과목 | 회계시스템 |
| 결제방법 | 조직 관행 + 회계 |

**제목과 과거 문서만으로는 한 항목도 채울 수 없다.** 초안이 할 수 있는 건
"항목 이름과 순서를 맞추는 것"까지고, 값은 전부 `(   )` 로 비게 된다.

- **필요: `첨부정보`** — 요구사항의 "첨부 기반 하이브리드 OCR(VLM + DI)"이 여기에 직결된다.
  첨부에서 금액·기간·대상을 뽑지 못하면 지출 문서 초안은 **골격만 있는 껍데기**다.
- 지출은 20건 중 4건, 경기도서관 8건 중 2건이다. 결재문서에서 드물지 않은 유형이다.

### 2-2. `연결문서` — 보고·알림 문서는 앞 문서를 가리킨다

- 8942(기성검사 완료 알림)는 본문 첫 항목이 **다른 부서 문서번호를 인용**하며 시작한다
  ("○○과-{번호}({날짜})호와 관련입니다").
- 11698·12039(기성검사 결과 보고)는 **앞선 용역 계약·검사 요청 문서**가 있어야
  "무엇의 기성검사인지"가 성립한다.
- 8938(추진 결과 보고)은 8872(추진 계획)의 후속이다. 계획 문서를 모르면
  "결과"에 무엇을 써야 하는지 알 수 없다.

- **필요: `연결문서`** — 요구사항의 "기획품의 → 실행품의" 연결이 정확히 이 구조다.
  같은 조직 문서를 유사도로 찾는 것만으로는 **선후 관계**를 알 수 없다.
  문서번호 인용을 파싱해 링크를 만들어야 한다(본문에 문서번호가 그대로 있으므로 가능하다).

### 2-3. `조직관행` — 짧은 문서에는 항목 구조가 아예 없다

경기도서관 8건 중 **번호 항목이 있는 문서는 3건뿐**이다(지출 2 + 알림 1).
나머지 5건은 한두 문단으로 끝난다.

- 결과보고 3건: 282~403자, 항목 없음
- 계획 1건: 355자, 항목 없음

즉 "1. 목적 / 2. 추진내용" 같은 정형 서식은 **이 조직의 관행이 아니다.**
초안이 그런 서식을 만들어내면 오히려 실제와 멀어진다.

- **필요: `조직관행`** — 초안 형식을 하드코딩하면 안 되는 이유다.
  프롬프트에 형식을 넣지 않고 "기존 문서 형식을 따르라"고만 지시한 게 이 때문이다.
- **평가상 함의**: 항목 재현율은 지출 문서에서만 의미가 있다.
  짧은 보고 문서는 분모가 0이라 구조 지표로 잴 수 없고, 핵심어·길이로만 봐야 한다.

### 2-4. `기타` — 제목에 이미 답이 들어 있는 경우

12016(의원 요구자료 제출)처럼 제목이 "무엇을 제출한다"를 다 말하는 문서는
본문이 형식적인 한 문단이다. 초안 생성의 가치가 낮다.

## 3. 정리 — 초안 생성에 필요한 입력

우선순위 순.

1. **`첨부정보` (필수)** — 지출·계약 문서 본문은 사실상 첨부에서 옮겨 적은 값이다.
   첨부 추출 없이는 초안이 골격만 남는다. **요구사항의 첨부 하이브리드 OCR이 여기 걸린다.**
2. **`연결문서` (필수)** — 보고·알림 문서는 앞 문서를 인용하며 시작한다.
   본문에 문서번호가 그대로 있으므로 링크 생성은 기술적으로 가능하다.
   유사도 검색만으로는 선후 관계를 못 만든다.
3. **`조직관행`** — 정형 서식을 가정하면 안 된다. 조직마다 문서가 훨씬 짧을 수 있다.
4. **검색 품질** — 같은 조직은 잘 찾지만(2.38/3) **같은 유형**을 찾는 건 75%다.
   유형 태그를 메타데이터로 갖고 있다면 검색에 함께 쓰는 게 낫다.

## 4. 생성 단계 (qwen3:8b, 8케이스 × 초안 3개 = 24개)

BM25 로 검색한 top-3 을 컨텍스트로 넣고 temperature 0.2/0.6/1.0 으로 3개씩 뽑았다.
**34분** 걸렸다(케이스당 약 4분, 초안당 14~60초).

| 지표 | 값 |
|---|---|
| 항목 재현율 | **0.0%** |
| 핵심어 재현율 | **56.2%** |
| 길이 비율 | 1.21배 |

### 4-1. 항목 재현율 0.0% 는 지표의 한계다

실제 문서의 항목 머리글과 초안의 머리글을 **앞 6글자 일치**로 셌는데, 초안이
`지 출 액` 이라 쓰고 실제는 `지 급 액` 이라 적는 식으로 한 글자씩 어긋난다.
내용은 맞는데 지표가 0 이 된다. **구조가 아예 없다는 뜻이 아니다** —
초안은 번호 항목을 만들었고, 실제 문서 8건 중 항목이 있는 건 3건뿐이라 분모도 작다.
이 지표는 이 표본에서 쓸모가 없다.

### 4-2. 초안이 지어내는 것 — `연결문서` 의 결정적 증거

24개 초안을 훑은 결과다.

| 관찰 | 개수 |
|---|---|
| 다른 문서번호를 **인용**한 초안 | 15 / 24 |
| 인용된 문서번호 중 **실제 존재** | **1 / 7** |
| 인용된 문서번호 중 **지어낸 것** | **6 / 7** |
| 값을 `(   )` 로 비운 초안 | 11 / 24 |
| 붙임을 적은 초안 | 8 / 24 |
| gold 실명이 등장한 초안 | 14 / 24 |
| 다른 기관명이 섞인 초안 | 3 / 24 |

**모델은 "앞 문서를 인용하며 시작한다"는 형식은 정확히 학습했는데, 어느 문서인지
알 방법이 없어 번호를 지어낸다.** 6/7 이 존재하지 않는 번호다.
법령 인용도 같다 — 없는 「AI 윤리 가이드라인」 같은 근거를 만들어낸다.

이것이 **`연결문서` 정보가 왜 필요한지에 대한 가장 강한 근거**다.
형식을 흉내 내는 능력은 이미 충분하고, 빠진 건 **무엇을 가리켜야 하는지**다.
요구사항의 "기획품의 → 실행품의 연결"이 없으면 초안은 그럴듯한 거짓 인용을 단다.

### 4-3. 검색이 잘못 끌어오면 초안이 오염된다 — `기타`

12012(초과근무수당 지출) 초안 3개 **전부**에 `제주시` 머리글이 들어갔다.
BM25 가 같은 "지출" 유형인 `제주시일자리에너지과-40914` 를 top-3 에 올렸고,
모델이 그 문서의 발신명의를 그대로 베꼈다.

- **필요: 검색에 조직 필터** — 같은 조직으로 먼저 좁히고 유형으로 정렬해야 한다.
  지금은 유형 유사도가 조직 경계를 넘는다.

### 4-4. 값은 비웠다 — 지시는 지켰다

`(   )` 로 비운 초안이 11/24 다. "참고 문서에 없는 금액·날짜를 지어내지 말라"는
지시를 **금액에 대해서는** 지켰다는 뜻이다. 2-1 에서 예측한 대로
**지출 문서 초안은 골격만 남고 값은 전부 빈칸**이 됐다.

- 즉 첨부 추출을 붙이면 그 빈칸이 그대로 채워질 자리다. 구조는 이미 맞다.

### 4-5. 실명이 초안에 복사된다

24개 중 14개에 gold 의 실명이 들어갔다. 참고 문서에서 사람 이름을 그대로 옮긴 것이다.
초안 단계에서 사람 이름을 미리 채우는 건 대체로 원하는 동작이 아니고,
운영 시에는 **초안 생성 컨텍스트에서 인명을 마스킹**하는 편이 낫다.

## 5. 정리 — 초안 생성에 필요한 입력 (실측 후)

| 우선순위 | 정보 | 실측 근거 |
|---|---|---|
| 1 | **`첨부정보`** | 지출 초안이 값을 전부 `(   )` 로 비움(11/24). 구조는 맞고 값만 없다 |
| 2 | **`연결문서`** | 인용한 문서번호 6/7 이 지어낸 것 |
| 3 | **검색 조직 필터** | 다른 기관 머리글이 초안에 복사됨(3/24) |
| 4 | `조직관행` | 항목 있는 문서가 8건 중 3건뿐. 정형 서식 가정 금지 |
| 5 | 인명 마스킹 | 참고 문서 실명이 초안에 복사됨(14/24) |
