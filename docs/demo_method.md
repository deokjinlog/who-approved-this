# 로컬 데모와 E2E 테스트

측정 코드가 낸 숫자를 **눈으로 확인하기 위한** 로컬 데모다. 제품이 아니다 —
인증이 없고 localhost 전용이며, 계산은 전부 `tracks/` 코드를 그대로 호출한다.

---

## 1. 구성

### 계층

```
api/models.py     요청·응답 스키마 (pydantic)
api/services.py   tracks/ 코드를 호출해 결과를 만든다. 로직을 여기서 새로 쓰지 않는다
api/routers.py    HTTP 경로만. 서비스를 호출해 스키마로 감싼다
api/app.py        FastAPI 조립 + 기동 시 웜업
ui.py             Gradio 한 파일. **services 를 직접 호출한다** (HTTP 안 탐)
```

`services.py` 가 부르는 것은 전부 트랙 코드다. 이를 위해 트랙 쪽 함수를
공개 이름으로 바꿨다(`t1c.load_docs`, `t1d.build_prompt`, `t1d.generate`,
`t1d.ollama_embed`) — 복붙 대신 재사용하려는 것이다.

### 엔드포인트 4개

| 경로 | 입력 | 출력 |
|---|---|---|
| `POST /approval-line/predict` | `{org, title, body}` + 쿼리 `exclude_doc_id`, `mask`(기본 true) | `{masked, org, predictor, cells[{role,title,name}], reference_doc_ids[], reference_count}` |
| `POST /draft/generate` | `{org, title, n}` + 쿼리 `exclude_doc_id` | `{org, title, retriever, model, drafts[], references[{chunk_id,doc_id,org,doc_type,score}], context_same_org_only, names_masked, note}` |
| `GET /docs`, `GET /docs/{id}` | 쿼리 `org` | `DocInfo` — 문서번호·생산일자·담당부서·쪽수·글자수·gold 유무·**직위 목록**. **사람 이름 없음** |
| `GET /orgs` | — | 조직 키 목록 |

Swagger 는 `/docs` 가 아니라 **`/swagger`** 다. `/docs` 를 문서 목록 API 가 쓰고 있어
기본 경로와 충돌했다.

### Gradio 탭 2개

| 탭 | 호출 | 화면 |
|---|---|---|
| **결재선** | `services.predict_approval_line()` + `services.gold_cells()` | 왼쪽 gold / 오른쪽 예측을 **칸 단위 표**로. 틀린 칸 빨간 배경 |
| **초안** | `services.generate_draft()` + `services.actual_body()` | 왼쪽 실제 문서 / 가운데 초안 3개 탭 / 오른쪽 검색된 참고 문서 |

**UI 는 HTTP 를 타지 않는다.** 같은 프로세스에서 `services` 를 직접 부른다.
그래서 UI 화면은 gold 실명을 그대로 보여줄 수 있고(로컬 비교용), API 응답은
별도로 마스킹된다(§5).

두 탭 모두 **고른 문서를 참고에서 제외**한다(leave-one-out). 측정 조건과 같게 맞추려는 것이다.

### 기동

```bash
uv run wat serve                      # http://127.0.0.1:8000/swagger
uv run wat ui                         # http://127.0.0.1:7860

# 로컬 모델을 붙이면 규칙 기반 대신 LLM 경로가 켜진다
WAT_LLM_MODEL=qwen3:8b WAT_EMBED_MODEL=bge-m3 uv run wat ui
```

| 환경변수 | 없을 때 | 있을 때 |
|---|---|---|
| `WAT_LLM_MODEL` | 결재선 = `BaselineVote`(다수결), 초안 = **검색 결과만** | 결재선 = `VoteTitlesLLMNames`, 초안 생성 |
| `WAT_EMBED_MODEL` | 검색 = BM25 | 검색 = Hybrid(BM25+벡터 RRF) |

**예측기 기본값은 `vote_titles+llm_names`** 다 — 12케이스와 재표집 40회에서 직위·이름·칸수
모두 단독 방식보다 낫거나 같았다. **마스킹 기본값은 켬**이다.

## 2. 요청 한 건의 흐름

UI 결재선 탭에서 문서를 고르고 실행했을 때.

```
ui.run_approval(choice)
  └ ui._doc_id() / _org_of() / _title_of()        드롭다운 문자열에서 문서 식별
  └ services.predict_approval_line(org, title, exclude_doc_id=doc_id)
      ├ services._docs()                          20건 본문·조직·gold 결재선 (lru_cache)
      │   ├ t1d.load_docs()                       PDF 텍스트 레이어
      │   └ t1c.load_docs()                       gold 결재선
      ├ refs = 같은 org, 자기 자신 제외            leave-one-out
      └ VoteTitlesLLMNames.predict(refs, target)
          ├ BaselineVote.predict()                칸 구조·직위 (즉시)
          └ LocalLLM.predict()                    이름
              ├ build_prompt()                    참고 7건 × 본문 1500자
              └ ollama_chat()                     POST /api/chat  ← 대부분의 시간
  └ services.gold_cells(doc_id)                   비교용 정답
  └ ui._cells_table(gold, pred)                   HTML 표, 틀린 칸 빨간 배경
```

### 소요시간

| 구간 | 웜업 전 | 웜업 후 |
|---|---|---|
| **첫 요청** | **17.3초** | **4.7초** |
| 2회차 이후 | 4.7초 | 4.7초 |

시간의 대부분은 `ollama_chat()` 한 번이고, 그중에서도 **프롬프트 처리**다
(참고 7건 × 1500자 ≈ 1만 자). 나머지 단계는 캐시가 걸려 있어 밀리초 단위다.

웜업은 `api/app.py` 의 startup 훅 → `services.warm_up()`.
처음엔 `"ping"` 한 번으로 했는데 **효과가 없었다**(17.3초 유지). 원인이 모델 로딩이
아니라 긴 프롬프트 처리였기 때문이다. **실제와 같은 크기의 예측**을 한 번 돌리도록
바꾸니 첫 요청이 4.7초가 됐다.

초안 생성은 케이스당 **29~60초**다(스타일 3개 × 생성). 이건 줄이지 않았다.

## 3. E2E 1차 — 발견과 수정

브라우저 에이전트가 사용자처럼 클릭해 테스트했다. 코드는 건드리지 않고,
경기도서관 문서 3건으로 두 탭을 돌린 뒤 Swagger 에서 예측 1회를 호출했다.
결과는 리포 밖 `DATA_ROOT/e2e_report_v1.md`.

**모든 요청이 200 이었고 JS 예외·깨진 렌더링은 없었다.** 문제는 전부 **내용** 쪽이었다.

| # | 문제 | 원인 | 조치 |
|---|---|---|---|
| **D-1** | 초안에 `## 참고문서 N`, `본문:` 마커와 **참고 본문 전체가 복사** | ollama `/api/generate` 는 **이어쓰기** 엔드포인트다. 프롬프트가 문서 모양이면 모델이 그 문서를 계속 이어 쓴다 (직접 재현해 확인) | `/api/chat` 으로 전환(system/user 분리). 출력에 마커가 남으면 실패로 세는 `has_prompt_leak()` 추가 |
| **D-2** | 초안 3개가 **바이트 단위로 동일** | temperature 는 **정상 반영되고 있었다**(0.0/1.0/1.5 해시 전부 다름). 출력이 짧아 분포가 뾰족했던 것 | 다양성 축을 **스타일**(요약형/상세형/격식형)로 교체. 3개가 같으면 `identical_drafts` 로 기록 |
| **D-3** | 초안이 대상 제목과 **무관한 참고 문서 표 조각**을 냄 | 참고 본문이 길어 모델이 마지막 문맥을 이어 씀 | 참고 본문 **800자 제한**, 대상 제목을 프롬프트 **앞뒤 두 번** 명시, 앞 200자에 제목 내용어가 없으면 **1회 재생성**(`on_topic()`) |
| **D-4** | API 응답 `cells[].name` 실명 그대로. `허 채 윤` 처럼 **자간 벌린 이름 미탐지** | (a) 엔드포인트에 마스킹이 아예 없었다 (b) 정규식이 연속 글자만 잡았다 | (a) `mask` 파라미터 **기본 켬** (b) 글자 사이 `\s*` 허용 (c) CLAUDE.md 에 정책 명시 |
| **D-6** | 협조 행 **미예측**(빨간 칸 6개 중 4개) | **버그가 아니라 데이터 한계.** 협조가 있는 문서가 조직마다 1건뿐이라 leave-one-out 시 참고에 협조 예시가 **0건** | 프롬프트에 협조 조건 추가 + 다수결이 못 만든 역할은 LLM 제안을 쓰는 폴백. **이 표본에서는 여전히 0** |
| **D-5** | 첫 호출 **17.3초** | 모델 로딩이 아니라 **긴 프롬프트 처리** | 실제 크기 예측으로 웜업 |

### 전 / 후

| 항목 | 전 | 후 |
|---|---|---|
| 프롬프트 마커 | 4개 | **0** |
| 초안 3개 동일 | 2/3 문서 | **0/3** |
| 사안 불일치 | 12012 3개 모두 | **0** |
| 실명 노출(초안) | 1건 | **0** |
| API 이름 마스킹 | 미적용 | **기본 켬** |
| 첫 호출 | 17.3초 | **4.7초** |
| 협조 칸 | 미예측 | 미예측 (데이터 한계) |

**부수 효과** — `/api/chat` 전환으로 결재선 예측도 올랐다(12케이스):
`llm_local` 이름 64.2 → **72.5%**, 결합 예측기 이름 66.9 → **72.5%**.

## 4. 왜 숫자 측정에서는 안 보였나

**이게 E2E 를 돌린 이유다.** 여섯 개 전부 T1c·T1d 지표를 통과하고 있었다.

| 문제 | 지표가 못 잡은 이유 |
|---|---|
| **D-1 프롬프트 노출** | 평가 지표가 **핵심어 재현율**이었다. 참고 본문이 통째로 복사되면 핵심어가 오히려 **늘어서 점수가 올라간다.** 지표가 정확히 반대 방향을 가리켰다 |
| **D-2 초안 동일** | `best-of-3` 만 기록했다. 3개 중 최고 점수만 보니 **셋이 같은지 다른지는 애초에 계산하지 않았다** |
| **D-3 사안 불일치** | 핵심어를 **실제 문서**에서 뽑는데, 같은 조직 문서라 어휘가 겹친다. 다른 문서 내용을 베껴도 핵심어가 잡혀 점수가 안 떨어졌다 |
| **D-4 마스킹** | `results/*.json` 에는 **값을 아예 안 담는다**. 그래서 유출 검사(grep)가 늘 0건이었다. 실명은 **화면과 API 응답**으로만 나가는데 그 경로를 검사한 적이 없었다 |
| **D-6 협조 행** | 칸 수 일치를 **역할 4개 중 몇 개**로 세는데, 협조가 0/0 인 문서가 대부분이라 그 문서들은 만점을 받는다. **협조가 있는 소수 문서의 실패가 평균에 희석**됐다 |
| **D-5 지연** | 배치 실행은 20건을 연속으로 돌려 **첫 호출 비용이 전체에 묻힌다.** 사용자는 첫 호출 하나를 본다 |

정리하면 **집계값은 개별 실패를 감춘다.** 특히 D-1 은 지표가 문제를 *보상*하고 있었고,
D-4 는 검사 지점이 실제 유출 경로와 달랐다. 화면으로 한 번 보는 게 필요했다.

## 5. 마스킹 정책

### 무엇을 가리나

**사람 이름만 가린다.** 직위·부서·기관명은 가리지 않는다 — 그게 측정 대상이기 때문이다.
카드번호·계좌·업체명은 마스킹 대상이 아니라 **애초에 결과에 담지 않는 것**으로 다룬다
(CLAUDE.md 원칙에 명시).

마스킹 함수는 `t1d_draft.mask_names()` 이고, 가릴 이름은 **gold 명단**에서 온다.
본문에서 이름을 추정하지 않는다. `홍길동` 뿐 아니라 `홍 길 동`, 줄바꿈이 낀 표기도
잡는다(글자 사이 `\s*` 허용) — 공문은 자간을 공백으로 벌려 찍기 때문이다.

### 경로별로 다르다

| 경로 | 사람 이름 | 이유 |
|---|---|---|
| `results/*.json` | **아예 안 담음** | 커밋 대상이다. 일치 여부·개수만 기록 |
| 콘솔 출력 | 안 담음 | 실패 목록도 `문서 id / 필드 / 사유` 로만 |
| **API 응답** | **마스킹 (기본 켬)** | 프로세스 밖으로 나가는 경로다. `mask=false` 로 끌 수 있다 |
| **초안 생성 컨텍스트** | 마스킹 | 참고 본문의 실명이 초안에 복사됐다(24개 중 14개) → 마스킹 후 1/8 |
| **UI 화면** | 그대로 표시 | 로컬 데모에서 gold 와 눈으로 비교하려면 필요하다. UI 는 HTTP 를 타지 않고 `services` 를 직접 부른다 |
| `DATA_ROOT/` 원본·gold | 그대로 | 리포 밖이고 커밋되지 않는다 |

### 리포에 안 남는 걸 어떻게 보장하나

세 겹이다.

1. **구조적으로** — 결과 JSON 을 만드는 코드가 값을 담지 않는다. 담을 수 있는 자리가 없다.
2. **데이터 위치** — PDF·gold·초안·검토본은 전부 `DATA_ROOT`(리포 밖)에 있고
   `.gitignore` 이전에 **애초에 리포 안에 두지 않는다**.
3. **검사** — 커밋 전에 gold 명단·제목으로 `results/` 전체를 훑는다.
   최근 검사 결과 **이름 0건 / 제목 0건 / 담당자 0건**.

한계도 적어 둔다 — 이건 **알려진 이름 목록 기반**이라, 명단에 없는 사람 이름이
본문에 있으면 못 가린다. E2E 에서 부분 마스킹된 카드번호와 업체명이 초안에 남은 것도
같은 이유다(이름이 아니라 마스킹 대상이 아니었다).

## 6. 지금 데모의 한계

**① 단일 사용자, 인증 없음.** `127.0.0.1` 바인드가 유일한 보호막이다.
동시 요청 처리·세션·권한이 전혀 없다.

**② 상태가 프로세스 메모리에 있다.** 문서·색인이 `lru_cache` 라 **파일이 바뀌어도
재기동 전까지 반영되지 않는다.** E2E 에서 "드롭다운이 20건에 머물러 있다"고 나온 게
그 증상이다(수집분이 병합되지 않은 것과 별개로, 병합돼도 재기동이 필요하다).

**③ 로컬 모델 지연.** 결재선 4.7초, 초안 29~60초. 실사용 감각과 거리가 있다.
스트리밍이 없어 초안은 다 만들어질 때까지 빈 화면이다.

**④ 20건짜리 코퍼스에 고정.** 조직·양식·유형이 좁다(§ `t1_method.md` 6절).
새 문서를 넣으려면 gold 를 사람이 만들어야 한다.

**⑤ 오류 처리가 없다.** ollama 가 죽으면 빈 문자열이 돌아오고 화면에 그대로 빈칸이 뜬다.
사용자에게 "모델이 응답하지 않는다"고 알리지 않는다.

**⑥ UI 와 API 가 같은 프로세스다.** UI 는 HTTP 를 타지 않아 **API 경로의 회귀를
UI 로는 잡을 수 없다.** D-4(API 마스킹 누락)가 그래서 화면에서는 안 보였다.

**⑦ 초안 품질 지표가 화면에 없다.** 사람이 눈으로 비교해야 한다.

> **그대로 가져갈 것 — 3계층 분리(스키마/서비스/라우터)와 "서비스는 트랙 코드를 호출만
> 한다"는 규칙, leave-one-out 로 자기 문서를 참고에서 빼는 평가 방식, 마스킹을
