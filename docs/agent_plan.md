# 전자결재 에이전트 — 설계와 로드맵

## 목표

로그인한 사용자가 제목(과 본문·첨부)을 넣으면 **결재선 · 초안 · 요약 · 확인 필요 목록**을
한 번에 돌려준다. 회사 기능 ①(초안) ②(결재라인 자동 삽입) ③(첨부 요약)을 한 흐름으로 묶는다.

## 설계 원칙 — 워크플로형 (자유 도구 호출형이 아니다)

| 실측 | 원칙 |
|---|---|
| 결재선: 규칙 뼈대 95% > 이력 81% > LLM 단독 58% | **LLM 은 후보 안에서만 고른다** |
| 초안 자유 생성: 인용 문서번호 7개 중 6개가 허구 | **소스가 없는 칸은 비우고 "확인 필요"** |
| 요약: 근거를 주면 숫자 근거율 99~100% | **숫자 칸은 정규식으로 옮긴다** |
| E2E: 지표는 통과했는데 화면에서 결함 6개 | **모든 출력에 근거 태그** |

## 흐름 (`src/who_approved_this/agent.py` · `ApprovalAgent.handle()`)

| 단계 | 방식 | 근거 파일 | 현재 |
|---|---|---|---|
| 사용자 식별 | 명부 조회 | `DATA_ROOT/t1/roster.tsv` (리포 밖) | gold 에서 생성 |
| 업무항목 | LLM (목록 안에서) | `rules/worktype.yaml` | 본문만 85%, 제목+본문 경기도서관 8건 100% |
| 결재선 | 전결표 + 조직도 | `rules/approval.yaml` | 직위 95% (경기도서관 8건, 귀납 규칙) |
| 결재선 (공식 규정) | 슬롯 체인 + 직무대리 + 별표 조회 | `rules/gapyeong.yaml` + 별표1 3,325행 | 가평군 held-out 30건(A-2): 경로 96.3%, 채점 가능 종점 12/13, 부군수 금액 구간 첫 적중. **국장 이하 종점은 공개 원문으로 관측 불가**(부단체장 이상만 공개) |
| 초안 | 템플릿 칸 채우기 | `templates/draft/*.yaml` | 회계지출만 귀납, 나머지 기본 구조 |
| 요약 | 템플릿 + 근거 검사 | `templates/summary.yaml` | 신규 |
| 확인 필요 | 규칙 | — | 출처가 귀납인 규칙·빈 필수 칸을 자동으로 올린다 |

## 병목 — 전부 데이터다

1. **전결 분기 데이터** — 가평군 A(30건, 전부 군수) + A-2(held-out 30건, 군수 15 / 부군수 15).
   부군수 vs 군수 경계는 채점된다(12/13). **국장 이하 종점은 공개 원문으로 관측 불가** —
   원문공개가 "부단체장 이상 결재문서"만 대상이다. 전 구간 채점은 회사 내부 데이터가 필요하다.
   경로는 슬롯 + 직무대리(인사 데이터)로 held-out 96.3%. 못 맞힌 칸은 전부 인사 발령 사례였다.
2. **서식** — 초안 템플릿은 기관 서식에서 와야 한다. 20건 귀납은 한계가 분명하다.
3. **첨부** — 초안 금액 칸과 요약 기능 모두 첨부가 입력이다.
